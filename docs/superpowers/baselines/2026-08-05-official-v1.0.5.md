### Bash Detection Baseline Issue

The unmodified `doctor` command reported:

```text
Bash shell: unavailable
```

Its diagnostic searched the conventional paths:

```text
C:\Program Files\Git\bin\bash.exe
C:\Program Files (x86)\Git\bin\bash.exe
```

However, `where.exe bash` found Bash executables in a nonstandard Git installation on drive `D:` as well as Windows Bash aliases. Therefore the current failure is specifically an official Bash discovery/configuration mismatch on this machine, not proof that no Bash executable exists.

This is recorded for Phase 1 diagnosis. Phase 0 did not alter PATH, persisted DevSpace configuration, shell discovery code, or the running launcher.

## Known Limits

1. **Dependency audit:** A fresh npm audit reports 14 vulnerabilities: 1 low, 8 moderate, and 5 high. Dependency remediation requires a separately designed and tested change.
2. **Bash discovery:** The official CLI fails to detect the machine's nonstandard Git Bash location unless the runtime environment or configuration supplies the shell path. This directly affects later Bash capability work.
3. **Tarball reproducibility:** The locally generated pure-tag tarball is structurally valid but is not byte-identical to the published registry tarball.
4. **Host integration:** Phase 0 did not replace the global package or reconnect ChatGPT to the source build, so it does not prove real MCP-host behavior from the fork.
5. **Feature scope:** Git policy changes, commits, notifications, Scheduler behavior, Worker transports, and Python PoC migration remain unimplemented.
6. **Upstream main:** The enhancement baseline is intentionally anchored at `v1.0.5`; later upstream changes on `upstream/main` have not yet been evaluated or merged.
